# PR REVIEW

次のステップに従い、GitHub 上のプルリクエストをレビューしてください。

以下、ファイルはすべて `/tmp/YYYYMMDD_HHMM_(title)/` に保存してください。
明記されているファイル以外にも、必要に応じて追加のファイルを保存することができます。

## Step1: サブエージェントを使った指摘候補の作成

レビューに必要な観点を網羅的に列挙し、 `review_criteria.md` に保存してください。
それごとにサブエージェントを生成して、指摘候補を網羅的に作成させてください。指摘候補は `review_(criteria)_candidates.md` に保存してください。
独立性を保つため、サブエージェントには、この SKILL を読まないように指示してください。
自分で直接指摘候補を作成しないでください。

## Step2: 指摘候補の分類

指摘候補が返ってきたら、それらを以下に基づいて分類して、`total.md` に保存してください。

```保存内容
番号. タイトル
主要なファイルパス
問題の分類/発生条件の分類
問題と発生条件についての説明
修正案についての説明
```

### 問題の分類

- 動作・品質の問題: バグや仕様不適合、性能問題など、コードの動作や品質に関する問題
- 保守・開発の問題: コードの可読性や保守性、開発者体験に影響を及ぼす問題
- 表記・体裁の問題: コードのフォーマットやコメントの書き方など、見た目や読みやすさ、チーム内規約や一貫性に関する問題

### 発生条件の分類

- 通常利用で発生：一般的な操作・データ・運用で問題が成立する。
- 特定条件で発生：特定の入力、状態、環境、障害、タイミングがそろうと問題が成立する。
- リスクまたは将来的に発生：現在の動作では問題が成立することは確認できなかったが、仕様追加やコード変更などを仮定すると成立する。
- 動作上の問題を伴わない：可読性、保守性、表記・体裁などについての指摘。

## Step3: まとめと報告

レビューの結果をまとめ、報告してください。指摘候補の分類結果をもとに、問題の重要度や対応の優先度を考慮して報告内容を整理してください。
また、 `total.md` のリンクも共有してください。
