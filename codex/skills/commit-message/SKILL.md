# Commit Message

git の変更内容と現在のステージング状態を調べ、適切なコミットの分け方とメッセージを提案してください。

1. コミットに含める変更を整理してください。
  - 変更に複数の内容が含まれる場合、それぞれのまとまりに応じてコミットの分割を検討してください。
  - 未完の変更はユーザーに通知し、特に指示がなければコミット対象から除外してください。
  - 今コミットに含める変更、あとにする変更、コミットするべきでない変更を区別してください。
  - あとにする変更やコミットするべきでない変更は、理由とファイルパスをユーザーに伝えてください。

2. コミットごとに、適切なコミットメッセージを提示してください。
  - 何が変わったのか、なぜその変更が必要だったのかを明確にしてください。
    - 変更点を見るだけでは直接わからないようなポイントを重視してください。
    - 不具合修正では、変更前に起きていた具体的な問題を明記するようにしてください。
  - 「案内」「説明」「処理」などの名詞は、その対象が理解できるように書いてください。
  - 会話や差分を知らない人が、対象と修正理由を理解できるか確認してください。
  - 文体や雰囲気をできるだけ既存のコミットメッセージに合わせてください。
  - ただし、コミット内容の重要度や複雑さに合った長さ・詳細さで記述してください。
    - 内容が長大・複雑かつ重要な場合は、題名と本文を分けて記述してください。

3. 提案したコミットを作成するためのステージング操作を提示してください。
  - 現在のステージング状態と違いがある場合は、ファイルパスを含めて報告してください。
  - コミットごとに、対象の変更のみをステージングするために必要なコマンドを提示してください。
  - ファイル内の一部の変更だけを対象にする場合は、必要に応じてパッチの作成も検討してください。
